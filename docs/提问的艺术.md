# 提问的艺术（How to Ask）

> 这是给「西门子百宝箱」用户的提问与贡献指南。提问前花两分钟读完，能省掉你和维护者来回好几轮的沟通成本——也更容易得到高质量的回答。

---

## 一、遇到问题，先做这三步

**1. 重启**
约一半的"软件抽风"重启就好——先重启软件，必要时重启电脑。很多问题在重启后就消失了，省一次提问。

**2. 自查**
- 看 README 和软件内置帮助
- 看软件的"常见问题"（FAQ）

**3. 看有没有人问过**
- GitHub Issues：https://github.com/chenpiyanghappy/SiemensInstallHelper/issues
- CNB 仓库对应的讨论区

别人问过的问题，答案可能已经躺在里面了。**带着"我已经试过这些"来问，本身就是最好的礼貌。**

> 如果这三步都没解决，再进入下一步。

---

## 二、提问前，先收集这些信息

问得越具体，解决得越快。提问时请带上：

| 信息 | 怎么获取 |
|------|---------|
| 软件版本号 | 软件"关于"窗口里 |
| Windows 版本 | 按 `Win + R`，输入 `winver` 回车 |
| 西门子软件版本 | TIA Portal V20 / WinCC / STEP7 / PLCSIM 的版本号 |
| 错误信息 | 警告框文字、错误码（截图） |
| 日志 | 软件日志 / Windows 事件日志（可让软件自动打包） |
| 复现步骤 | 从"打开软件"开始，一步一步写清楚 |

---

## 三、提问话术模板（复制改一改就能用）

**标题**：`[软件版本号] 一句话描述问题`
> 示例：`[v1.2.0] 安装 TIA Portal V20 时提示需要重启，重启后仍提示`

**正文**（按这个结构填）：

```
- 软件版本：
- 系统环境（Windows 版本 / 内存 / 磁盘剩余空间）：
- 西门子软件及版本：
- 我做了什么：
  1. ...
  2. ...
- 出现的问题：
- 我尝试过的解决方法：
  1. ...
  2. ...
- 日志 / 截图：（以附件形式附上）
```

**要点**：日志比描述值钱一万倍。有日志一定附日志，有截图一定附截图。

## 五、怎么提 PR（贡献代码）

如果你会改代码，欢迎直接提 PR——维护者会认真 review，并把你加入贡献名单：

1. **Fork 仓库**：在 GitHub 上把仓库 Fork 到自己的账号
2. **建分支**：`git checkout -b fix/xxx`（修 bug 用 `fix/`，加功能用 `feat/`）
3. **改代码**：改完先在本地测试通过
4. **提交**：写好 commit message——说清楚"改了什么、为什么"
5. **提 PR**：在 GitHub 发起 Pull Request，说明：
   - 改了什么
   - 为什么这么改
   - 测试情况如何
6. **等 review**：维护者可能提出修改意见，礼貌沟通，改完再 push

> CNB 仓库的合并请求（Merge Request）流程与 GitHub 类似。

## 六、沟通公约

- **一次说清**：环境、步骤、日志一次给全，别挤牙膏式你问我答
- **有礼貌**：这个项目由个人维护、AI 辅助开发，作者无偿付出时间和精力，尊重是相互的
- **不催促**：别隔 10 分钟催一次；真的急，在标题里说明紧急原因
- **不阴阳**：有问题好好说，吐槽解决不了问题
- **可标注 AI 辅助**：本项目由 AI 辅助开发，贡献者在 PR 里也可以注明自己的 AI 辅助情况
